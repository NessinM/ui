Agent UI is a family of components for conversations with an AI agent, in a panel or a page. It builds on [Chat UI](/ui/docs/chat) and the shared [Composer](/ui/docs/components/composer): where an agent and a chat mean the same thing, such as the scroll container, the message shell, timestamps, Markdown and streaming text, Agent UI uses the chat part. The components handle presentation, local interaction and screen reader announcements. Your application owns the agent runtime, messages, persistence and authorization.

The family is new. This page covers the conversation, messages, message actions, the announcer and the motion policy. Composer, turn content and chrome parts follow.

## Start here

- **Build a conversation:** install `@coss/agent`, then use the [minimal example](#minimal-conversation).
- **Working as an agent:** read [this page as Markdown](/ui/docs/agent.md). The [agent registry source](/ui/r/agent.json) includes file contents and dependencies. Use the exported TypeScript props as the API contract.

## Install

Configure coss ui using [Get started](/ui/docs/get-started), then install the family:

```bash
npx shadcn@latest add @coss/agent
```

This installs the agent source into your configured components directory under `agent/`, including its hooks and helpers. It also installs `@coss/chat` and `@coss/composer`, which the family builds on, and the coss components they need.

## Minimal conversation

A conversation needs a bounded height, a chat scroll controller, messages and one announcer. Render the announcer once per conversation, outside the scrolling log.

```tsx
"use client";

import { AgentAnnouncer } from "@/components/agent/agent-announcer";
import { AgentConversation } from "@/components/agent/agent-conversation";
import { AgentMessage } from "@/components/agent/agent-message";
import { useAgentAnnouncer } from "@/components/agent/hooks/use-agent-announcer";
import type { AgentPhase } from "@/components/agent/lib/get-agent-announcement";
import { useChatScroll } from "@/components/chat/hooks/use-chat-scroll";

type Message = { id: string; from: "user" | "assistant"; text: string };

const labels = {
  done: "Response ready",
  failed: "Something went wrong",
  stopped: "Response stopped",
  thinking: "Thinking",
  working: "Working",
};

export function AgentChat({
  messages,
  phase,
}: {
  messages: Message[];
  phase: AgentPhase;
}) {
  const scroll = useChatScroll({ itemCount: messages.length });
  const announcer = useAgentAnnouncer({ labels, phase });

  return (
    <div className="flex h-[32rem] flex-col">
      <AgentConversation
        scroll={scroll}
        label="Conversation with the assistant"
        jumpLabel="Latest"
      >
        {messages.map((message) => (
          <AgentMessage
            key={message.id}
            from={message.from}
            streaming={phase === "working" && message === messages.at(-1)}
          >
            {message.text}
          </AgentMessage>
        ))}
      </AgentConversation>
      <AgentAnnouncer announcer={announcer} />
    </div>
  );
}
```

## Component map

Import components directly from their files. There is no provider.

| Area | Components | Responsibility |
| --- | --- | --- |
| Conversation | `AgentConversation`, `useChatScroll` | Chat scroll viewport and end following, quiet by default, keeps its place in popover crossfades |
| Message | `AgentMessage` | User bubble or full-width reply on the chat message shell, avatar, actions and footer slots, streaming state |
| Content | `ChatMessageText`, `ChatMessageMarkdown`, `ChatMessageCaret`, `ChatMessageTimestamp` | Chat parts for text, Markdown, the streaming caret and timestamps |
| Actions | `AgentMessageActions`, `AgentMessageAction`, `AgentMessageCopyAction`, `AgentMessageEditAction` | Toolbar revealed on hover and focus, generic icon action, copy and edit |
| Announcer | `AgentAnnouncer`, `useAgentAnnouncer`, `getAgentAnnouncement` | One status region per conversation and the rule for what it says |
| Motion | `useAgentReducedMotion` | Reduced-motion check for motion timed in JavaScript |

## Conversation

<ComponentPreview name="p-agent-1" />

`AgentConversation` is `ChatConversation` with agent defaults, so it takes the same props: a `scroll` controller from `useChatScroll`, a `label` for the log and a `jumpLabel` for the jump-to-latest button. It follows new content while the reader is at the bottom and shows the jump button once they scroll up. Update `itemCount` when messages change, and `layoutKey` for other size changes such as a growing streamed reply. Set `scroll.atBottomRef.current = true` before appending the user’s own prompt so the conversation follows it. See [Scrolling and replies](/ui/docs/chat#scrolling-and-replies) for the rest of the controller.

It differs from `ChatConversation` in three ways:

- **`live` defaults to `"off"`.** A polite log would read every streamed chunk. Announce phase changes through the [announcer](#announcer) instead.
- **Messages are spaced** in a column with a `gap-6` and top padding. Override it with `contentClassName`.
- **It keeps its place in popover crossfades.** A coss popover crossfades a cloned snapshot of its old content when it switches between triggers, for example when a floating panel moves from one conversation to another. A DOM clone keeps attributes but not scroll position, so the outgoing transcript would jump to its top. The conversation writes its scroll offset to `--agent-conversation-scroll-top` on the viewport, which the clone inherits, and translates the snapshot’s content back by that offset. Outside a popover this does nothing.

## Messages

<ComponentPreview name="p-agent-2" />

`AgentMessage` requires `from`, either `"user"` or `"assistant"`. User messages render in the chat bubble at the end of the row. Assistant replies render full width with no bubble, so Markdown, tables and code have room. String children render through `ChatMessageText`; pass `ChatMessageMarkdown` or your own content for anything richer.

Pass the agent’s identity mark, such as an avatar or a logo, to `avatar` on assistant replies; user messages ignore it. It sits in the chat avatar column, at the top of the reply. Mark it `aria-hidden` when it’s decorative, as it is when the conversation’s label already names the agent.

Set `streaming` while the reply is still arriving. It sets `data-streaming` on the content, as in chat. Put `ChatMessageCaret` inside the last text block and remove it when the stream ends. Render the `footer` from the start, for example with a “Writing…” label that becomes a `ChatMessageTimestamp`, so the row doesn’t jump when the reply finishes.

The root is the chat message layout with `data-slot="agent-message"` and `data-from`. Use `render` to change its element.

## Message actions

<ComponentPreview name="p-agent-3" />

Pass an `AgentMessageActions` toolbar to the message’s `actions` slot. It needs a `label`, and arrow keys move between its actions. Every action is a toolbar part, so place actions inside it. Inside a message, the actions stay hidden on fine pointers until the message is hovered or focused, or one of their popups is open. They’re always shown on coarse pointers, where there’s no hover. Set `actionsAlwaysVisible` on the message to keep them shown, for example on the latest reply. Hidden actions keep their space, so revealing them never moves the conversation.

- **`AgentMessageCopyAction`** copies `text`. While the text is copied, it shows a check and its `copiedLabel` as the tooltip. Its accessible name stays `label`, so screen readers hear the result once: announce `copiedLabel` from `onCopy` through the [announcer](#announcer).
- **`AgentMessageEditAction`** calls `onEdit`. Your application decides what editing means, such as moving the prompt back into the composer.
- **`AgentMessageAction`** is the generic icon action for anything else, such as retry. Pass the icon as children and a `label`, which names the button and fills its tooltip unless you pass `tooltip`.

An action with nothing to do is a disabled button, never one that only says so: an `AgentMessageAction` without `onClick` or `render` is disabled, even with `disabled={false}`, and so is a copy action with empty `text`. Don’t render actions your application can’t perform.

## Announcer

<ComponentPreview name="p-agent-4" />

Each conversation has one status region. `useAgentAnnouncer` decides what it says, and `AgentAnnouncer` renders it. Feed the hook the agent’s current `phase` and localized `labels`. It announces transitions, never streamed text:

| Transition | Announced |
| --- | --- |
| First render, or a new `conversationId` | Nothing; the current state is the baseline |
| Into `thinking` or `working` from a settled phase | That phase’s label |
| Between `thinking` and `working` | Nothing |
| Into `approval`, `done`, `stopped` or `failed` | That phase’s label, or `detail` when given |
| A new `detail` within `approval` or `failed` | The new detail, such as a second error |
| Into `idle` | Nothing |

A phase without a label is never announced. Pass the error message or the approval question as `detail`. For results that aren’t phases, such as a copied message or a copied conversation, call `announcer.announce(text)`. Repeating the same text is read again.

`getAgentAnnouncement(previous, next)` is the pure rule behind the hook. Use it to test your own mapping from your agent runtime to phases.

## Reduced motion

Every transition the agent parts add has a reduced-motion path: CSS transitions use `motion-reduce:transition-none`, and loops such as the streaming caret run only under `motion-safe`. Parts the family composes, such as chat’s jump to latest and coss tooltips, follow their own primitives. For motion timed in JavaScript, such as an exit delay before a crossfade, read `useAgentReducedMotion()` and skip the delay when it returns `true`. Follow the same policy in your compositions.

## Approvals, feedback and recovery

These parts sit inside a turn: an approval card when the agent needs a yes before acting, feedback under a finished reply, and recovery when a turn fails. Every word comes from your application through props, and every result that should be heard goes through the [announcer](#announcer): pass `announcer.announce` to `announce`. None of them adds its own live region.

| Component | File | Responsibility |
| --- | --- | --- |
| `AgentApprovalCard` | `agent/agent-approval-card.tsx` | One approval with idle, responding, approved, denied and error states |
| `AgentApprovalGroupCard` | `agent/agent-approval-card.tsx` | Several approvals answered together, with approve all and skip all |
| `getAgentApprovalState`, `getAgentApprovalGroupShared` | `agent/lib/get-agent-approval-state.ts` | The pure rules for a card’s state and a group’s shared wording |
| `AgentResponseFeedback` | `agent/agent-response-feedback.tsx` | Thumbs up and down, reasons and details, saving and failure |
| `getAgentFeedbackAction`, `getAgentFeedbackSubmission` | `agent/lib/get-agent-feedback.ts` | What a rating press does, and what a thumbs down submits |
| `AgentErrorRecovery` | `agent/agent-error-recovery.tsx` | A failed turn’s message with retry and check-status actions |

### Approval card

<ComponentPreview name="p-agent-20" />

`AgentApprovalCard` asks the question in `prompt` and calls `onRespond` with `"approved"` or `"denied"`. Its labels are the default verbs, `approve` and `deny`, the resolved lines, `approved` and `denied`, and the `error` line. A prompt’s `approveLabel` and `denyLabel` replace the verbs for that action, such as “Cancel booking”. The prompt can also carry a `context` line, `details` lines and a `badge`.

The card renders its resolved states itself, so your transcript doesn’t need its own “Approved” row. It derives one state from three inputs, by this rule:

| Input | State |
| --- | --- |
| `decision` is set, from your agent runtime | `approved` or `denied`, whatever else is true |
| `responding`, or `onRespond`’s promise is running | `responding`: both actions are disabled |
| `error`, or `onRespond`’s promise rejected | `error`: the error line shows, and the person can answer again |
| None of these | `idle` |

Return a promise from `onRespond` when your runtime confirms answers, or pass `responding` and `error` yourself. A rejection also announces the `error` label. Set `decision` once the runtime records the answer; the card keeps it even if a late response or a stale error arrives. Announce the question itself through the announcer’s `approval` phase, with the question as `detail`.

When answering removes the focused button, the card moves focus to the resolved line, or back to the button after an error, so keyboard users keep their place. Set `disabled` while the agent can’t take an answer, such as during another turn. `getAgentApprovalState` is the rule behind the card; use it to test your mapping from runtime states.

### Group approval card

<ComponentPreview name="p-agent-21" />

`AgentApprovalGroupCard` takes `items`, each an `id` and a `prompt`, and answers them together: approve all or skip all. It calls `onRespond` once with the decision, and your application answers each item. It renders nothing when `items` is empty.

When every item asks the same `question`, the card asks it once, using the first item’s `sharedQuestion` when it has one, such as a plural. When the questions differ, each item shows its own. When every item has the same `approveLabel`, approve all uses that verb. `getAgentApprovalGroupShared(items)` returns both decisions. The group takes the same `decision`, `responding`, `error`, `disabled` and `announce` props as the single card.

### Composing a crossfade

Neither card animates into what comes next. To crossfade a card into a status line once it’s answered, wrap it in your own element and select on its stable attributes: `data-slot="agent-approval-card"` or `"agent-approval-group-card"` on the root, and `data-state` with the card’s state. Inside, the footer is `agent-approval-footer`, the resolved or error line is `agent-approval-status`, and the actions are `agent-approval-approve` and `agent-approval-deny`. Time any exit in JavaScript with `useAgentReducedMotion()`, and give CSS transitions a `motion-reduce:` variant.

### Response feedback

<ComponentPreview name="p-agent-22" />

`AgentResponseFeedback` is a pair of thumbs for a finished reply. Place it inside `AgentMessageActions`, beside the copy action. It’s controlled: pass the shown rating as `value` and update it when `onFeedback` resolves.

- **A thumbs up** calls `onFeedback` with `{ rating: "positive", reasons: [], details: "" }`.
- **A thumbs down** opens a dialog first. With `reasons`, the person picks at least one; without them, the dialog asks only for details. `detailsMaxLength` caps the details field, and the submitted details are trimmed and capped to it.
- **Pressing the shown rating again** calls `onFeedback(null)`. Keep the rating shown if your application can’t delete a stored one.

While `onFeedback` runs, the pressed button shows a spinner and repeat presses are ignored. When it rejects, the `error` label shows beside the thumbs, or in the dialog, and is announced; a saved rating announces `submitted`. Retrying is up to your application, for example one delayed retry inside `onFeedback` before it rejects. Show feedback with the message’s `actionsAlwaysVisible` when the error must stay visible without hover.

### Error recovery

<ComponentPreview name="p-agent-23" />

`AgentErrorRecovery` shows a failed turn: your message as children, and up to two actions. Pass `retryLabel` and `onRetry` to run the turn again, and `checkStatusLabel` and `onCheckStatus` when the turn may have changed something and running it again could repeat that. An action renders only when it has both a label and a handler. Your application decides what failed, from its own failure codes, and which action fits. Remove the slot once recovery starts, and announce the failure through the announcer’s `failed` phase with your message as `detail`.

Place it where the reply would have been, inside the failed `AgentMessage` or its `footer`. The root is a `div` with `data-slot="agent-error-recovery"`; use `render` to change its element.

## Before shipping

Check keyboard-only operation of message actions, a screen reader with streamed replies, a touch device and reduced motion. Test long replies, stopped and failed turns, and switching conversations, with your own agent runtime.
